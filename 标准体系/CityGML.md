CityGML 2.0 = 用 XML(GML)描述"**三维城市里的对象是什么、长什么样、属性有哪些、互相什么关系**"的语义信息模型。它管的是"语义 + 几何 + 拓扑 + 外观",不只是画个三维形状。
- **2.0**:概念模型和 XML(GML)编码**绑死在一起**,模型长啥样、就必须用 GML 存
- **3.0**:把**概念模型**(用 UML 定义"城市对象有哪些、什么关系")和**编码**(具体怎么存)彻底拆开

1. **语义与几何分离**
    
    - 一个"城市对象"(比如一栋建筑)是语义实体,带属性(名称、用途、建造年代…)
    - 它下面可以挂**多个几何表示**——同一个建筑,LOD1 一个盒子、LOD3 一个带门窗的精细模型,**都指向同一个"建筑"语义对象**
2. **多尺度 LOD(0~4)**
	+ 同一对象在不同精细度下有不同几何
    
3. **模块化 + ADE 扩展**
    - 标准拆成多个**模块**,各管一类对象
    - **ADE(应用领域扩展)**:你可以在不破坏标准的前提下,自己加私有字段——这是它能被各国各地区"本地化"的关键


### LOD体系
2.0 是**一个数字** LOD0~4;
3.0 把它拆成**三个独立维度**:
- **空间维度**:是 2D 还是 3D
- **几何精度**:几何画得多细
- **语义精度**:带了多少语义属性

> 含义:不再是"0~4 选一档"的死板分级,而是可以"几何粗、语义细"或"2D 但语义丰富"这种**自由组合**。比如一张 2D 平面图,也能带丰富的语义——这在 2.0 里做不到。


### 模块结构
#### 基础类
- **Core(核心)** → 定义最基类 `_CityObject`,所有城市对象都从它派生
- **Appearance(外观)** → 纹理、颜色、材质
- **TexturedSurface(纹理表面)** → 给建筑面贴纹理的辅助模块
- **Generics(通用对象)** → 兜底用的,标准没定义的对象先放这

#### 主题类
|模块|描述什么|
|---|---|
|**Building**|建筑(最核心)|
|**Bridge / Tunnel**|桥梁、隧道|
|**Transportation**|道路、铁路、广场|
|**Relief**|地形(TIN、规则格网)|
|**WaterBody**|河流、湖泊|
|**Vegetation**|树木、植被(单株或面)|
|**LandUse**|土地利用(地块用途)|
|**CityFurniture**|路灯、长椅等小设施|


#### 组织类
- **CityObjectGroup** → 把多个对象打组(比如"XX片区"把几栋楼组在一起)


### 编码
#### 3.0编码格式
- **GML 编码**(延续 2.0 的 XML 风格)
- **CityJSON 编码**(JSON 格式,轻量、适合 Web 和前端)
- **数据库编码**(直接进 3D City Database 这类空间数据库)







### 2.0 vs 3.0
|          | CityGML 2.0 |       CityGML 3.0        |
| :------: | :---------: | :----------------------: |
|    发布    |    2012     |           2021           |
| 概念 vs 编码 |     绑定      |       **分离**(多种编码)       |
|   编码格式   | 只有 GML(XML) | GML / **CityJSON** / 数据库 |
|   LOD    |  单一数字 0~4   |    **三维度**(维度×几何×语义)     |
|  时间/动态   |      ❌      | ✅ Versioning / Dynamizer |
|    点云    |      ❌      |       ✅ PointCloud       |
|    室内    |      弱      |        增强(Space)         |
